Transport Header Offset (thoff) is the offset to the transport layer header of a packet, for example the tcp header of a packet. The offset points to the header relevant to the protocol that the table does matches on. For etables, this is gonna be the offset to the layer 2 header, for layer 3 tables like ip6 and ip will look at their respective layer 3 headers, and the list goes on for all the others.
hotdrop: hotdrop exists so one can ask the kernel to immediately drop the packet by setting it. netfilter modules can make use of it to filter out packets, this is how obsolete iptables or the (newer) netifrc drops matches or how those that arent allowed by default are dropped by some other default settings in a build in module of netfilter. This in most cases not for security purposes, but rather for a mix of performance(cutting out unnecessary traffic), reducing power consumption, etc.
netfilter tables:netfilter tables dictate the priority(if there are two rules, both using the "raw hook" for interception then you will look at the table to see whch one runs first), help the respective netfilter module to know the application, and also convey intent. No two tables will have the same priority, but sometimes it dosent matter anyway. For example Etable modules will get to see the packets before  ip6, ip and arptables, but between  ip6, ip and arptables, the order really dosent matter, precicely because the .family member of xt_match defines the respective table, and only that table will see that packet. In the case of Etables, its gonna be NFPROTO_UNSPEC, where as for others, its gonna be something else, which means that while etables can see the packets of the others, the others cant see the packets. This is ofcourse, just an example, maybe there are more tables, or some sophisticated work arounds, but the default way of how netfilter tables work.
sk_buff: sk_buff is a handle to the data buffer of the packet.
